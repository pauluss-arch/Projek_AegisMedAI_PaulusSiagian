# Cryptographic Decision Record: AEAD for AegisMed AI

## Need -> Mechanism -> Rationale

| Need | Mechanism | Rationale |
|---|---|---|
| Keep sensitive record contents confidential and detect unauthorized changes | AES-256-GCM using Node.js native `node:crypto` | AEAD provides encryption and authentication together; no separate unauthenticated encryption or custom MAC composition is needed. |
| Bind encrypted content to its patient or record context | Optional Additional Authenticated Data (AAD), such as a stable patient-record identifier | AAD is authenticated but remains visible. Changing or removing it causes authentication to fail. Do not put confidential data in AAD. |
| Avoid repeating a nonce with a key | Generate a fresh 96-bit (12-byte) IV with `crypto.randomBytes(12)` for every encryption | GCM security depends on nonce uniqueness per key. The IV is stored with the encrypted payload and is not secret. |
| Verify authenticity and integrity before accepting plaintext | 128-bit (16-byte) GCM authentication tag | Decryption does not return plaintext unless Node.js verifies the tag successfully. |
| Keep keys unpredictable and out of source control | Generate 256-bit keys with `generateCsprngKey()` and load deployment keys from `AEAD_SECRET_KEY` | Keys must be delivered through an environment/secret manager outside Git. Never use a generated test fixture as a deployment key. |

## Parameters and payload

- Algorithm: AES-256-GCM.
- Key: exactly 32 bytes, provided as exactly 64 hexadecimal characters.
- IV/nonce: 12 bytes generated by the operating system CSPRNG for each encryption.
- Authentication tag: 16 bytes.
- Ciphertext, IV, and tag are encoded as hexadecimal. If supplied, AAD is returned as a string alongside them so the same context can be authenticated during decryption.

The public module functions accept the key explicitly to make key handling visible at call sites. `getAeadSecretKeyFromEnvironment()` reads and validates `process.env.AEAD_SECRET_KEY`; application code should call it only in server-side code. Do not import this Node.js module into client components or expose the environment key to browsers.

## Validation and fail-closed behavior

- Reject empty plaintext/AAD, malformed or incorrectly sized keys, malformed ciphertext hex, non-96-bit IVs, and non-128-bit tags before decryption.
- A well-formed ciphertext with a wrong key, changed ciphertext, tag, IV, or AAD throws `AuthenticationFailedError`.
- Decryption buffers plaintext internally and only returns it after `decipher.final()` authenticates successfully. On failure it clears the temporary plaintext buffer and throws a generic error without including plaintext or low-level crypto details.
- `generateCsprngKey()` returns key material. Treat its output as a secret; do not log it or commit it.

## Key storage and scope

Set `AEAD_SECRET_KEY` in the deployment environment or a secret manager. For local work, use an ignored `.env` file and do not commit it. The `.env.example` value is only an instruction placeholder, not a usable key. Tests use synthetic hard-coded keys and synthetic messages only.

This module provides AEAD primitives and tests; it does not by itself encrypt existing Prisma columns or migrate previously stored records. Integrating encryption into persistence requires a separate data-format/key-rotation plan and must not silently change existing records.
